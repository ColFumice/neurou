# neurou 的编程范式：声明式 · 数据流 · 规则约束

> 这份文档回答一个反复被问的问题：**neurou 到底是什么编程逻辑？面向对象？面向过程？**
> 结论先行：**都不是。** 它是一张「因果网」的声明式语言——用**规则与约束**描述一张**有状态的数据流图**，
> 运行时负责让数据在图上流淌。准确叫法是「**规则式数据流声明语言**（rule-based dataflow, declarative）」，
> 「面向关系（relationship-oriented）」只是对它的直觉命名，不是学术界标准范式。

## 1. 和 OOP / POP 的差别

| | 面向对象（OOP） | 面向过程（POP） | neurou |
|---|---|---|---|
| 世界由什么组成 | 对象（属性 + 方法） | 一条条执行流程 | **弦与关系**（状态 + 耦合 + 阈值 + 约束） |
| 谁在控制 | 你调用 `lizard.attack(player)` | 你写 `if/else` 与循环 | 编译器排好顺序，运行时每拍自动演化 |
| 变化怎么发生 | 方法调用 | 语句逐行执行 | **数据一变，下游按耦合自动传导** |
| 代码形状 | 类、方法、继承 | 函数、分支、循环 | `弦 / 耦合 / 回路 / 力迫 / 和弦 / 公理 / 信号` |
| 作者的工作 | 指挥对象做事 | 画流程图 | **设计条件：当某根弦波动时，别的弦怎么动** |

一个最小例子：

```nro
实体 使者
  叙事弦 信任
    类型 数值 0..100
    基线 50
    悬崖 25
    安全 70

耦合 信任 → 筹码 同向 0.35 延迟 1

回路 退让: 信任↓ → 让步↑ → 信任↑

力迫 信任崩塌
  当 信任 < 25
  效果
    耐心 -= 15
  不可逆
```

这里没有一行“执行命令”：没有 `if (trust < 25) { ... }` 的流程控制，也没有 `npc.onBetray()` 的方法调用。
你描述的是：**哪些量存在、它们怎么互相拉扯、什么条件下会发生什么**。剩下的由编译器与运行时完成。

## 2. 三个支柱 + 一条底线

### 支柱一：声明式（Declarative）——描述「是什么」，不描述「怎么做」

- 你声明一根弦的类型、取值范围、基线、阈值、响应曲线；
- 你声明耦合的方向、极性、强度、延迟；
- 你声明力迫的条件与效果、公理、结局。
- 没有 `for` / `while`，没有流程语句；循环由「回路」表达，分支由「条件 + 规则」表达。

### 支柱二：数据流（Dataflow）——因果涟漪

- 每拍固定顺序结算：投递耦合 → 执行动作 → 判定力迫/和弦 → 传导变化 → 校验公理 → 判定结局 → 信号。
- 一根弦的数值变化会按耦合自动流到相邻弦；延迟以「拍」为单位，避免同拍递归。
- 玩家不是“调用函数”，而是**注入一个扰动**：选一个动作 / 拨一次弦；之后世界自己演化。
- 确定性：同一 seed + 同一动作序列 = 同一局；`snapshot()` / `branch()` 可以冻结与分叉。

### 支柱三：规则与约束（Rules & Constraints）——世界不散架

- **规则**：力迫、和弦、动作是挂在弦网上的触发机关；条件成立就点火。
- **约束**：公理是不可触碰的不变量；回路闭合力、偏序成环、阈值可达性等由编译器检查。
- **验证**：编译器是第一验证器（语法 / 语义 / 体验三级诊断），音准仪是第二验证器（批量模拟后的可玩性评估）。

### 底线：LLM 只做解释器，不做立法者

LLM 只把「状态切片 + 类型约束」翻译成表达片段（台词、视觉提示），
不生成世界规则、不改 HOD、不携带全局上下文。规则层是宪制，LLM 是法官，不是独裁者。

## 3. 八弦调律台是这个范式的直接投影

调律台不是仪表盘，而是一件乐器。它把范式**空间化**了（v0.8 起，屏幕上的值就是世界里的值）：

| 屏幕上的东西 | 在范式里对应什么 |
|---|---|
| 横轴 | 时间 / 因果流向（一拍一拍向右） |
| 纵轴 | 状态值的刻度；**弦的基线纵坐标 = 世界里这根弦的当前值**（归一化后） |
| 弦的波形 | 数据流：一次扰动沿耦合传播、反射、衰减 |
| 拨动（点击 / 键盘） | **力迫**：`Universe.inject()` 往系统里注入一次变化；下一拍沿耦合传导 |
| 波峰与阈值线 | 规则点火的条件边界（悬崖 / 安全线）；弦靠近阈值时进入驻波态 |
| 两根弦的交点 | 跨系统耦合：两条状态曲线在空间里相遇的位置 |
| `Tab` 换焦点弦 | 切换「维度」：叙事 / 视觉 / 动画 / 物理 / 控制 / 空间 / 认知 / 关系 |
| `Esc` 总谱 | 从乐器退回谱面：看八类弦各自的签名波形 |

八类弦叠在同一个界面，正是「万物皆弦」的界面表达：
世界不是八个并列的模块，而是**同一张纸上八根互相干涉的弦**；
而它们的数据来自 `examples/tuner.nro` 编译出的 `WorldIR` 与逐拍 `Universe`——
你拖一根弦，是在改世界；世界下一拍把变化沿耦合传回给你看。

## 4. 常见误解

- **不是函数式编程**：虽然编译器内部有大量纯函数，但作者写的是状态与规则，不是表达式求值。
- **不是 ECS**：ECS 用组件/系统组织实体；neurou 的组织单位是「弦 + 关系」，实体只是弦的宿主。
- **不是节点图编辑器**：节点图描述“数据怎么连线计算”；neurou 描述“世界在什么条件下变化”，
  并且带编译器验证与批量模拟。
- **不是脚本语言**：脚本按时间顺序执行命令；neurou 声明不变量与响应，由运行时每拍演化。
- **「面向关系」不是学术标准词**：对外介绍时建议说「规则式数据流声明语言」，
  「面向关系」作为直觉补充即可。

## 5. 与《弦谱书》本体论的对应

| 本体论 | 工程实现 |
|---|---|
| Ω 元层宪法 | 公理 / 不变量 / 导出边界（部分仍是路线图） |
| V 基线宇宙 | `.nro` 里的 baseline + 初始状态 |
| HOD 弦网络 | `WorldIR`（弦、耦合、回路、规则、信号、结局） |
| 力迫 Forcing | 规则触发 + 玩家提供的扰动；`branch()` 生成 V[G] |
| Ultimate L 完备性 | 编译器验证 + 音准仪（不求 100 分，只求 60–85 的绿区张力） |

## 6. 现状与边界

- **已成立**：语言前端、`WorldIR`、确定性逐拍运行时、批量模拟、音准仪、CLI 都是这个范式的真实实现。
- **v0.8 已接回世界**：GUI 编译 `examples/tuner.nro`、逐拍运行 `Universe`、8 根弦的基线就是世界值；
  拖弦/拨弦通过 `Universe.inject()` 写回，下一拍沿耦合传导（GUI 里的值变化 = 世界里的数据流）。
- **v0.9 已闭合文本环**：`serialize(ir)` 把图投影回规范 `.nro`；用户手势后 GUI 把当拍值冻结成基线，
  经 dev 中间件写回 `examples/tuner.nro`，刷新从新基线开局（细节见 [序列化与写回](11-序列化与写回.md)）。
- **v1.0 起可编辑结构**：悬崖/安全阈值成为可拖对象，写回前强制编译校验，`Ctrl+Z` 撤销；
  基线/阈值/耦合强度都有纯函数编辑 API（见 [编辑与撤销](12-编辑与撤销.md)）。
- **未成立**：八类弦仍共用一个通用数值状态机，还没有“每类弦一个求解器”；
  「力迫」在代码里是条件触发规则，不是集合论意义上的可能性空间收缩；
  GUI 还不能增删弦/耦合/规则，序列化仍有损。
- 这些边界在 [架构完成度审计](08-架构完成度审计.md) 里有逐条证据，不要把设计愿景误读成已实现。
