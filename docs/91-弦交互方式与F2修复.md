# 弦交互方式与 F2 连续编辑修复（v5.34）

## 1. 三类弦交互

按弦类别固定交互方式：

| 方式 | 弦类别 | 键盘行为 | 判定点 |
|---|---|---|---|
| 持续 | 视觉、动画、物理、空间 | 按下持续发声，松手停止；不产生拨弦判定 | 无 |
| 头判 | 控制 | 按下立即发声/判定，松手不重复 | 按下时 |
| 尾判 | 叙事、认知、关系 | 按下拉弦、松手才发声/判定 | 松开时 |

- 只有尾判型保留「按住拉弦」的鼠标 pin；
- 持续型使用独立的持续声源，不进入拨弦/拉弦判定；
- 尾判型松手时发声 + 推动世界值；
- `STRING_INTERACTIONS` 是唯一映射，位于 `packages/core/src/ast.ts`。

### 为什么这样分

- **持续**：视觉/动画/物理/空间是连续介质，按住=持续驱动，松手=停止驱动。
- **头判**：控制是离散指令，按下即生效，松手不再重复。
- **尾判**：叙事/认知/关系需要“拉一下再放开”的意向动作，判定在松手时。
  只有这种弦才有拉弦操作。

## 2. F2 连续编辑修复

问题：

> 按住 ↑/↓ 调节点高度时按 ←/→ 切段，视觉选中了新段，但 ↑/↓ 还在改旧段。

修复：

- 切段时先把旧段当前值持久化；
- 停掉旧段的持续音；
- 把 `arrowTune.band / startValue / voiceId` 一起转到新段；
- 保持当前 ↑/↓ 方向和按住状态，继续调整新段；
- 松手时只对新段做最终持久化。

GUI 验收：

```text
按住上下键切段后控制新段 — sel 1→2, band=0.7443
```

## 3. 节拍（tick）是什么

`tick` 是世界的心跳，不是音频节拍器：

- 默认每 **480ms** 推进一拍；
- 每拍按系统阶段执行：投递/输入/规则/传导/校验/终止/观测/收尾；
- 力迫、动作耗时、冷却、场景切换、谱的受迫衰减、关系谱曲线采样、结局判定都以拍为时间单位；
- 它只驱动世界状态，**本身不发声**。

### 为什么你只听到键盘拨弦

- 默认 `tuner.nro` 没有音频端口/BGM，只有键盘拨弦声音；
- 想听 BGM：打开 `soundscape.nro` / `garden.nro` / `harbor.nro`（需首次手势，F4 音量不能静音）；
- 想听真实 Faust：打开新增的 `examples/audio-ports.nro`，按 Space 预览，等待 Faust wasm 编译；
- 想看节拍：GUI 底部会显示“第 N 拍”，每个 tick 世界会推进。
