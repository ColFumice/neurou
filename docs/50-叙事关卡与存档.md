# 叙事/关卡层：章节、续章与自动存档（v4.0）

> v3 的“可玩”是单世界的一局。v4.0 补叙事层最基础的三件事：
> 世界有章节名、结局后能去下一章、刷新能续上这一局。

## 1. 章节与下一章

世界元数据新增两个字段（仍写在 `世界` 块里）：

```nro
世界 温室
  章节 "温室"
  下一章 "examples/harbor.nro"
```

- `章节`：章节标题，页根节点暴露 `data-chapter-title`；
- `下一章`：只接受 `examples/<名字>.nro`，页根节点暴露 `data-next-chapter`；
- 世界结局出现后按 `N`，自动保存当前局并导航到下一章；
- 没有下一章时 N 无效；桌面键盘专属，移动端暂用 URL。

示例链：`garden.nro` → `harbor.nro`。

## 2. 自动存档

- 每 **4s**、以及 `pagehide` / 组件卸载时，把 `universe.snapshot()` 写入：

```text
localStorage['neurou.run.<world-file>:<seed>']
```

- 存档包含：world file、seed、tick、ended、完整 WorldState；
- 默认刷新**不自动续档**，避免覆盖“写回后从新基线开始”的既有语义；
- 需要续档时显式加参数：

```text
?world=examples%2Fgarden.nro&resume=1
```

- `?fresh=1` 清除该世界存档并从文件初值开始；
- 恢复后根节点 `data-resumed=true`、`data-save-tick=<tick>`。

## 3. 可观测属性

| 属性 | 含义 |
|---|---|
| `data-chapter-title` | 章节标题 |
| `data-next-chapter` | 下一章路径，或空 |
| `data-resumed` | 本次是否恢复了存档 |
| `data-save-tick` | 最近一次自动存档的 tick |

## 4. 验收

- 单元 **315/315**：新增章节/下一章元数据测试；
- GUI **245/245**：新增
  - 世界元数据带下一章；
  - 结局后 N 切到下一章；
  - 自动存档产生 save-tick；
  - `?resume=1` 刷新后续档。
- 自动存档不会写 `.nro`，只写 localStorage；
- `check` / `check:gui` / `check:docs` / `build` / 生产冒烟通过。

## 5. 边界

- 一章仍是一个独立 `.nro`；没有内嵌场景图/条件分支编辑器；
- `N` 只能前进一步，没有上一章/章节菜单；
- 移动端没有 N 键；
- 存档按“world-file + seed”隔离，不跨版本迁移；
- 没有云端存档/多槽位；
- 自动存档与写回是两套机制：写回改文件，存档只改 localStorage。
