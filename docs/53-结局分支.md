# 结局专属分支：不同结局去不同章节（v4.3）

> v4.0 的 `下一章` 是世界级的；同一个世界的所有结局只能去同一章。
> v4.3 允许每个结局声明自己的下一章。

## 1. DSL

```nro
结局 归港:
  当 航向 >= 90 且 灯塔 >= 65
  下一章 "examples/soundscape.nro"

结局 失踪:
  当 航向 <= 8
  下一章 "examples/garden.nro"
```

- 结局块字段：`当`、`下一章`；
- `下一章` 必须是 `examples/<名字>.nro`；
- 优先级：**当前结局的下一章 > 世界元数据「下一章」**；
- 行内写法 `结局 名: 当 ...` 仍然有效，只是没有专属分支。

## 2. GUI

- 结局出现后，`data-next-chapter` 会切换成该结局专属路径（没有则回退世界默认）；
- `N` / 点击右半屏 / 触控切章使用同一个目标；
- 保存与槽位逻辑不变。

示例链：

```text
garden ──下一章──→ harbor
harbor 归港 ─────→ soundscape
harbor 失踪 ─────→ garden
```

## 3. 验收

- 单元 **317/317**：新增结局专属下一章 IR/序列化、非法路径 2 项；
- GUI **252/252** 不回归（临时章节世界的结局带专属下一章）；
- `check` / `check:gui` / `check:docs` / `build` / 生产冒烟通过。

## 4. 边界

- 一个结局只能去一个下一章，不能 A/B 多选；
- 行内结局语法不支持 `下一章`，需要块写法；
- 分支图没有可视化，只存在于源文件/Runtime 数据；
- 章节路径仍限制在 `examples/`；
- 没有“未解锁分支”/条件显示。
