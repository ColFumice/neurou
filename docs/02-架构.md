# 架构与路线

## 1. 一条数据流

```
.nro 文本
   │  lexer.ts（缩进成块、全角容忍）
   ▼
Token 流
   │  parser.ts（递归下降，按声明分派）
   ▼
AST（ast.ts：一次性的文本形态）
   │  compiler.ts（收集 → 解析名字 → 类型检查 → 结构分析）
   ▼
WorldIR（ir.ts：弦网络图，唯一真源，可 JSON 序列化）
   │
   ├─▶ runtime/engine.ts   逐拍执行（Universe）
   ├─▶ runtime/simulate.ts 批量模拟（三种玩家模型）
   ├─▶ runtime/report.ts   音准仪报告
   └─▶ 调律台 GUI（v1.5：任意示例世界 + 多根弦 + 逐拍运行时 + IR 编辑（阈值/耦合/增删耦合）+ 行级写回 + 缓动撤销/按住绷弦） / 未来的弦包 / 语言服务
```

**顺序是刻意的**：先定图，再定文本。如果先定语法再让 GUI 去猜结构，文本形态会被
图形态反复推翻——对话里两代控制方案语法就是证据。

## 2. 弦网络图

`WorldIR` 是一张有类型的图，不是一棵 AST：

| 节点 | 字段 |
|---|---|
| 弦 | id、类型（七类 + 关系）、值域、基线、阈值、响应曲线、所属实体 |
| 实体 | id、种类、自由字段 |
| 规则 | 力迫 / 和弦 / 动作；条件、效果、不可逆、优先级、先于、重复与冷却 |
| 信号 | 条件 + 一组 cue（台词 / 视觉 / 音频 / 触觉 / 字幕） |
| 公理 | 不变量表达式 |
| 结局 | 终止条件 |
| 段落 | 曲式中的一段时间 |

| 边 | 字段 |
|---|---|
| 耦合 | from、to、极性、强度、延迟、曲线、条件；可归属某条回路 |
| 回路 | 一组有序耦合边 + 极性乘积 |
| 规则→弦 | 效果（set / add / sub / apply chord） |
| 信号→体验 | cue 投射 |

表达式在编译期已经**下降**成只含弦 id 的 `LExpr`（不再有路径字符串），
所以运行时不依赖名字解析，也不需要源文件。

## 3. 包边界

```
@neurou/core     无依赖。语言前端 + 图。任何宿主（GUI/CLI/服务）都能用。
@neurou/runtime  依赖 core。执行与观测，不依赖任何 UI。
@neurou/cli      依赖 core + runtime。只做参数解析与终端渲染。
@neurou/gui      v1.6 八弦调律台：打开示例世界、逐拍、inject、编辑阈值/耦合/增删耦合/增删弦、行级与块级写回、缓动撤销、按住绷弦。
（未来）@neurou/language-service  解析/诊断/模拟调度收敛为一个服务。
```

运行时永远不 import CLI 或 GUI。这是「前端极简、后端极繁」在代码上的投影：
GUI 是图的一个视图，不是逻辑的所在地。

## 4. 编译期检查

| 检查 | 实现 | 失败后果 |
|---|---|---|
| 名字解析 | 完整 id → 唯一短名 → 歧义报错；实体名可作引用值 | error，附带编辑距离建议 |
| 类型检查 | 数值 / 布尔 / 枚举 / 集合 / 文本 / 引用；效果与条件分别校验 | error |
| 阈值可达性 | 对照值域检查悬崖 / 安全线，检查两线不重合 | error |
| 回路闭合力 | 单环校验；极性乘积；闸门与结局接住 | 自我强化无闸门 = error |
| 和弦递归 | 把 `施加` 看成有向边做 DFS | error |
| 偏序 | 力迫 `先于` 图做 DFS 找环 | error |
| 公理 | 恒假；简单等式公理与 `=` 效果的直接对撞 | error |
| 静默失败 | 有阈值的弦是否被任何信号读取 | warning（体验级） |
| 死弦 / 死结局 | 读写集合；结局依赖的弦是否真的会被改变 | warning |
| 死局 | 运行时逐拍检测「无任何可做之事」 | 计入音准仪 |

诊断分三级（语法 / 语义 / 体验），因为**修改它们的位置不同**：
语法错去代码区改，语义错去结构区改，体验问题去总谱改。

## 5. 运行时

`Universe` 是不变式驱动的：

- 每拍固定顺序（见语言规范 §11）；
- 数值永远夹在量程内，夹掉的部分不传导；
- 耦合每拍只结算一次、延迟至少一拍，避免同拍递归导致的不确定性；
- 信号只在上升沿触发；
- 所有随机性来自显式 seed；`runOnce(ir, seed)` 可完全复现；
- `snapshot()` 深拷贝全部状态（含集合、冷却、延迟队列、RNG），`branch()` 由此分叉。

## 6. 模拟与音准仪

三种玩家模型不是「AI」，是三个下界：

| 模型 | 行为 | 用途 |
|---|---|---|
| 随机 | 均匀选动作，偶尔等待 | 难度下限与噪声基线 |
| 贪心 | 按效果的即时健康度打分 | 难度上限（能被无脑打穿就是太简单） |
| 学习 | 状态桶 + ε-greedy Q-learning，跨局累积 | 「这个世界学得会吗」 |

奖励 = 整体健康度的变化 × 10 + 结局奖励。健康度只统计「有明确好坏方向」的数值弦
（由悬崖/安全线的相对位置推导）。

音准仪分数 = 基础分 + 能动性 + 规则活性 + 结局熵 + 节奏离散 + 吸引子分散 − 硬缺陷惩罚，
满分压在 85 以下。

## 7. 扩展点

**加一种弦**：在 `ast.ts` 的 `STRING_KINDS` 加一项与关键字；在 `compiler.ts` 的
`KIND_SOLVER` 标注求解器；运行时若暂时没有求解器，就在 `signals` 层投射 cue，
不要在语言层假装它已经能跑。

**加一条诊断**：在 `compiler.ts` 的分析段加一个 `this.error/warn`，码段沿用
`NRO2xxx`（语义）或 `NRO3xxx`（体验），必须带一句人话 `hint`。

**接 GUI**：只需要两件事——把 `WorldIR` 读成视图；把编辑操作产生的新 `WorldIR`
重新序列化成 `.nro`。文本与图的双向绑定应当落在 `core`，不要在 GUI 里各写一套。

**接真实求解器**：在 `runtime` 里加一个 solver 适配层，按弦类型路由；
叙事弦仍由 `Universe` 驱动，视觉/物理弦订阅它的变化事件。

## 8. 已知边界

- v0.1 的视觉/动画/物理/空间弦只解析、只存图、只投射 cue，不驱动真实渲染或物理。
- 曲式只推进时间轴，尚不能作为条件被查询。
- 没有弦包格式与兼容协议；没有认证流程。
- 没有本地 AI 助手；外部 AI 通过复制粘贴 .nro 文本接入（与最终决策一致）。
- 批量模拟是「规则近似」：它验证机制与结局分布，不验证手感与画面。
- **v0.8 的调律台已读真实世界**：GUI 编译 `examples/tuner.nro`、逐拍跑 `Universe`，
  8 根弦的基线 = 世界弦值的归一化投影；拖弦/拨弦通过 `Universe.inject()` 写回世界，
  下一拍沿耦合传导。GUI 不再只是「与 IR 脱钩的乐器」。
- **v0.9 起 GUI 会把基线写回 `.nro`**：用户手势后约 0.7s，把当拍状态冻结成新基线，
  `serialize(ir)` 经 Vite dev 中间件写回 `examples/tuner.nro`（只写 examples/、原子写、不热重载）。
  刷新页面从新基线开局。生产包没有写回中间件（`data-save-state=disabled`）。
- **v1.0 起结构编辑开始**：焦点弦的悬崖/安全线成为可拖对象；写回前强制 `compileText` 校验，
  无效编辑拒绝写文件；`Ctrl+Z` / `Ctrl+Shift+Z` 撤销重做（历史仅在当前会话）。
  耦合强度编辑 API 已在 core 提供（有单测），GUI 手势尚未接。
- **v1.1 起世界可变**：dev 用 `?world=examples/xxx.nro` 打开任意示例世界，写回目标跟随当前文件；
  同类多根弦用 `←/→` 选择显示哪一根；波速整体放慢（视觉）。
  生产包仍固定内联 `tuner.nro`。
- **v1.2 起可编辑耦合**：焦点弦参与的耦合显示为左侧极淡竖线，悬停 + 滚轮调强度（0..2），
  写回走同一编译闸门与撤销；耦合投影在 `worldView.ts`（有单测），写入用 core 的
  `setCouplingStrength(Between)`。仍不能在画布上新增/删除耦合或改极性/延迟。
- **v1.3 手感**：鼠标/键盘按住 ≥180ms 会在按点钉出一个局部波峰（绷弦），松手才拨弦；
  `Ctrl+Z` / `Ctrl+Shift+Z` 用 620ms 缓动插值值与阈值再切换世界，不再闪回；
  动画期间暂停逐拍并拒绝编辑。
- **v1.4 写回保真**：保存时优先对源文本做**行级 patch**（只替换基线/阈值/耦合强度数字），
  注释/空行/缩进保留；结构变化或链式回路等无法 patch 时才回退 `serialize(ir)`。
  patch 入口在 core `patchWorldText(baseText, baseIR, editedIR)`，有 10 个单测；
  `.ink-app` 的 `data-save-mode=patch|fallback` 可观测。
- **v1.5 增删耦合**：`Shift+↑/↓` 选目标弦、`Shift+Enter` 切换耦合；core 新增
  `addCoupling` / `removeCoupling`（回路边受保护），patch 支持插入/删除耦合整行并保留注释。
- **v1.6 增删弦**：`Alt+Enter` 以焦点弦为模板新增同类弦，`Alt+Backspace` 删除焦点弦；
  core `addString` / `removeString`（删除前校验回路与规则/信号/结局引用，编译闸门兜底），
  patch 支持块级插入/删除弦声明。
- **v1.7 语言层新增 谱（编译期）**：独立的曲线数据资源（段/范围/插值/循环），不是第 9 类弦；AST/parser/compiler/IR/serializer 与 14 个单测、示例 examples/spectra.nro 已落地。运行时求解器（v1.8）与 GUI 谱模式（v1.9：F2、拖段点、缓动、patch 写回、撤销）已实现；音频音色绑定按 docs/19 v2.0 继续。
- **但还不是完整结构编辑器**：不能增删弦/耦合/规则/结局，同类多根弦不能同时叠一屏，
  序列化有损（注释、曲式名、`可见` 等 IR 不保存的信息会丢，见 `docs/11`–`docs/14`）。
- **超弦交互仍是界面机制**：驻波/干涉/D-膜/紧致化/对偶不改变 DSL 语义；
  Web Audio 的声音是 GUI 本地合成，不是运行时 8 类弦里的音频求解器。
- **8 类弦仍共用同一个数值求解器**：tuner.nro 只是每类弦各一根的演示世界，
  运行时依旧按值类型演化，没有「每类弦一个求解器」。

这些边界都写在语言规范 §14，避免把「路线图」误读成「已实现」。
