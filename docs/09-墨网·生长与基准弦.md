# 墨网·生长与基准弦（v0.5 交互设计）

> 这一轮只做两件事：让纸上的墨**自己活起来**，让调律台**能发声**。
> 它不改变语言、IR 与运行时；改的是“世界的一张视图”如何回应人的手。

## 0. 问题

v0.4 的墨网有三节点、四根横弦、两条回路，材质和 Tab 反色都已经到位，但用户的原话是：

> 「墨网太僵硬了。我希望它是那种点击后在点击的位置魔法似的生长然后消失的东西，
> 还有一种是贯穿屏幕的横向黑弦，点击后就可以塑造拟合点击位置的丝滑曲线波形，然后来发声。」

“僵硬”不是贴图不够多，而是**纸不对人的动作作反应**：弦只在悬停/拖动时被拉成同一个拱，点击空白没有任何回应，整个桌面上没有一样东西能发声。于是加了两条交互，并且顺手把静止的弦变活。

## 1. 设计约束（先定边界）

1. **不新增常驻 UI**：没有按钮、没有面板、没有数字、没有教程。所有操作都是“在纸上做手势”。
2. **仍然只有黑白**：墨 `#0b0b0b`，纸 `#fafafa`；反色时 `#f2f2f2` / `#000`。任何新图层都不许出现彩色。
3. **不接线就不算实现**：新交互必须被验收脚本量到（data 属性、像素、RMS），不能只靠肉眼说“感觉对了”。
4. **不把装饰写进世界**：墨晕和基准弦都不改 `WorldIR`、不写状态、不参与耦合。它们属于“调律台”这层乐器，不属于世界规则。
5. **可逆**：基准弦的塑形用 `Escape` 一键回直；墨晕自己会消失；声音 25s 无交互自动淡出。

## 2. 交互 A：点击处墨晕生长

**触发**：任意短按（按下到抬起位移 < 8px，鼠标左键/触摸）。拖动改值、拖动塑形不触发；基准弦的塑形带内也不触发（那里是乐器，不需要再叠一层墨）。

**为什么是 canvas**：一簇墨有 1000+ 段带笔锋的曲线，每帧只做填充/描边，用 SVG 会生成大量节点并触发 React 重排；canvas 单层绘制 + 预计算点列最稳。它 `pointer-events: none`，不抢任何手势。

**为什么是“生长”而不是“淡入”**：生长 = 形状随时间从种子点向外展开，长度、分叉、笔锋宽度都在变；淡入只是透明度变化。前者像墨落进水里，后者像 PPT 动画。

**为什么沿水平方向扩散**：墨网的语法是横向的——四根弦、两条回路、纸色墨流、基准弦全都沿 x 展开；如果点击长出的是一朵四面八方放射的圆花，它会成为这张纸上唯一一个“各向同性”的形状，和整套笔画语言打架。所以生长轴被约束在水平方向：主脊从点击点向左右抽长，侧枝只以浅角度（与水平 ≤30°）分叉，孢子主要横向漂移，峰值轮廓宽约为高的 3 倍。竖直方向只保留 40–80px 的呼吸起伏——仍然“活”，但不抢方向。

**时间线**（详见 [墨网测试体 §点击](07-墨网测试体.md#点击墨晕生长)）：种点 → 主须错峰抽长 → 花丝/孢子绽放 → 墨化雾散，总寿命 ~2.75s。形状由 `spawn 序号 + 坐标` 的确定性 seed 决定，便于截图复现与排查。

**同屏上限 6**：超过时最旧一簇进入 380ms 加速溶解，作为 ghost 墨迹淡出（不硬切），保证连点不炸帧、不糊满整张纸。

**降级**：`prefers-reduced-motion` 时静态出现 ~450ms、淡出 ~300ms；同屏像素与段落数仍受同一预算约束。

## 3. 交互 B：贯穿屏幕的基准弦

### 3.1 为什么是一根全宽单弦

调律台的隐喻是乐器：世界有四根“弦”，但它们各自绑定一个状态值，是**世界的弦**；人还需要一根**自己的弦**——像古琴的空弦、音叉的基准音，用来试音、调律、听出世界的调性。它必须：

- 贯穿全屏（x=0..1440），一眼看出不是某个实体的属性；
- 在底部（y=838），不打断上方实体列的阅读顺序，也不抢四根弦的悬停热区（压力弦热区到 y≈717，塑形带从 724 开始）；
- 比四根墨带更细、更黑：它是“尺子”，不是“血管”。

### 3.2 塑形数学

点击 `(x, y)` → `insertPoint`：x/y 先夹进 `[8,1432] × [742,872]`；与已有控制点 x 距离 <18px 时只改该点 y，否则按 x 插入。

曲线 = **PCHIP（Fritsch–Carlson 单调三次插值）** 穿过全部控制点，两端锚定 `(0,838)`、`(1440,838)`。选它而不是 Catmull-Rom，是因为 PCHIP 在相邻点之间不会过冲（不会出现“点击在线上、曲线却甩出去”的假峰），同时 C¹ 连续，视觉上足够丝滑。300 个采样，实测二阶差分最大值 0.05px。

视觉上，控制点做指数弹性逼近（τ≈45ms），所以点一下不是“跳变”，是“被按住再回弹”；每次点击还注入一个沿弦传播的衰减小波包（10–16px，~0.9s），静止时还有 ≤1.2px 的呼吸。

### 3.3 声音：曲线就是波形

- **拨弦**：Karplus-Strong。横向位置 → A 小调五声音阶 16 档（110–880Hz，3 个八度），纵向位置 → 明暗/强弱，左右 → pan；按「音高档 + 音色档」缓存 buffer。
- **持续音**：把当前曲线位移去均值、归一化、DFT 取 1–32 次谐波，塞进 `PeriodicWave`；110Hz 振荡器 + 低通 + gain 0.022 持续发声。**曲线的形状直接决定音色**——这是“塑造波形然后发声”的字面实现。切换音色时 40–80ms 交叉淡化。
- 首次 `pointerdown` 才建 `AudioContext`；浏览器拒绝时优雅降级为 `suspended`/`unavailable`，视觉与塑形不受影响。
- 25s 无交互淡出 drone；`Escape` 清空控制点、淡出并 suspend。
- 自动验收不靠耳朵：master 后挂 `AnalyserNode`，`window.__neurouWave.rms()` 给出真实信号；Playwright 断言点击后 RMS > 0.001。

### 3.4 手势语义

| 手势 | 结果 |
|---|---|
| 点击底部带任意位置 | 插入/移动一个控制点 + 拨一声 + 更新音色 |
| 按住上下拖 | 拉同一个控制点（连续塑形），松手后 250ms 更新 drone 音色 |
| `Escape` | 清空控制点、弦回直、声音淡出 |
| `Tab` | 反色；基准弦保持清晰（世界可以失焦，尺子不能） |

## 6. 取舍与下一步

**取舍**

- 墨晕是「横向墨痕」而不是圆花团：这是用户定的方向，也是刻意的——它和四根血管般的弦同属一种横向笔画语言；代价是竖直方向的表达力被主动限制。
- 基准弦不属于运行时：它发声、塑形，但不改变世界；想让它影响世界，需要先有 IR ↔ 文本双向绑定（见 [架构完成度审计 §10](08-架构完成度审计.md)）。
- 反色时基准弦不模糊：这是概念决定（尺子清晰），不是实现遗漏；要改只需把它包进 blur 层。

**下一步（按杠杆排序）**

1. 把基准弦的形状接进音准仪/调性：曲线上每个控制点 = 一个五声音阶音，塑形即“作曲”，再用音准仪给这个世界打分。
2. 让新交互产生数据：点击位置 → 状态切片 → LLM 表达片段（Tier 0 规则近似先做，不需要模型）。
3. `IR → 文本` 序列化 + 拖动写回 IR：拖一根弦后能存成 `.nro`，才算调律台。
4. 给声音一个显式静音入口（`M` 或长按），并记录用户是否发现它。
5. 移动端触摸实测：`pointer` 事件应该能用，但热区尺寸与移动端滚动冲突需要验证。
