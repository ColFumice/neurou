# 模块与 `引入`（v5.9）

> v5.9 给 DSL 加第一个组合原语：一个世界可以引入其他模块文件。
> 目前是“按依赖顺序合并后编译”，不是命名空间隔离——这是有意的第一版。

## 1. 语法

模块文件（`examples/lib/rain.nro`）：

```nro
叙事弦 雨量
  类型 数值 0..100
  基线 40
```

入口文件（`examples/storm.nro`）：

```nro
引入 "lib/rain.nro"

世界 风暴
  版本 0.1

系统 潮汐
  阶段 传导
  效果
    雨量 += 2

结局 停: 当 雨量 >= 100
```

规则：

- `引入 "相对路径.nro"` 只写在文件顶层；
- 路径相对引入它的文件；
- 模块不能声明 `世界`；世界只能写在入口；
- 循环引入、缺失模块报 `ProjectError`；
- 入口和模块的声明按依赖顺序合并，名字仍是全局的（没有命名空间）。

## 2. API

```ts
compileProject('examples/storm.nro', (path) => readFileSync(path, 'utf8'));
compileProjectFromFiles('examples/storm.nro', {
  'examples/storm.nro': entrySource,
  'examples/lib/rain.nro': moduleSource,
});
```

- `@neurou/core` 不做文件 I/O；`compileProject` 接收读取回调；
- CLI `neurou check/run/sim` 已改用 `compileProject`；
- 诊断使用合并后的 SourceFile，行号是合并文本的行号（第一版限制）。

## 3. 验收

- 单元 **337/337**：新增
  - 多文件合并与相对路径；
  - readFile 回调；
  - 循环/缺失/模块内世界声明报错。
- CLI 使用同一 API 编译入口；
- GUI 仍为 270，未改表现层（浏览器端模块打包后置）。

## 4. 边界

- 没有命名空间/导出表；所有名字全局；
- 没有选择性导入/别名；
- 没有模块级初始化/私有声明；
- 没有跨模块诊断文件定位；
- 浏览器 GUI 仍只打开单个 `.nro`，模块需要构建期打包；
- 没有版本/依赖锁定。
