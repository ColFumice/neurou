# 调律台用户测试包（v0.2 详细版）

> 注：v0.3 已改成**白纸全屏、无侧栏、无预览窗**的弦网络（见 [白纸黑线](03-最小GUI.md)）。
> 当前操作请用 [用户测试包 v0.3](05-user-test-kit.md)；本文件保留 v0.2 的详细问题清单，
> 其中「右下预览窗 / Tab 30 秒」等描述已过时。

> 目的只有一个：验证**第一眼是否被读成「编辑器/调律台」而不是「游戏」**，
> 以及用户会不会主动去碰弦。其他都是副产物。

## 0. 一页速览

| 项 | 值 |
|---|---|
| 人数 | 5 人（非程序员） |
| 单人时长 | 25–30 分钟 |
| 环境 | 桌面浏览器 1440×900，`pnpm gui` 打开的本地页面 |
| 每人间隔 | `localStorage.clear()` + 刷新 |
| 记录 | 屏幕录制 + 观察表 + 访谈录音（征得同意） |
| 核心指标 | 5 人中 ≥3 人，在第一分钟主动把界面描述成「编辑器 / 调律台 / 弦网络 / 可以改的世界」，而不是「游戏 / 关卡 / 画面」 |
| 次核心 | 5 人中 ≥3 人，在首次注视弦网络后 30 秒内主动悬停或拖动一根弦；30–60 秒为延迟发现；全程不碰为未发现 |
| 画面话术 | 统一说「这一版的画面是示意，重点看世界怎么反应，不看画面精不精细」 |

## 1. 招募

- 不写代码；职业尽量分散（编辑、教师、设计、运营、学生均可）。
- 玩过 1–2 款叙事游戏即可；不要招硬核关卡设计师（行业词会污染结果）。
- 没看过 neurou 的任何文档、截图、介绍。
- 每人一份小礼品或时薪；明确说「是测工具，不是测你」。

## 2. 测试前准备（观察者）

1. `pnpm gui`，打开 `http://127.0.0.1:5188/`。
2. 控制台执行 `localStorage.clear()`，刷新；确保默认视图是调律台。
3. 窗口 1440×900，缩放 100%，声音关闭（本版无音频输出）。
4. 开录屏（只录屏幕），准备秒表。
5. 观察者坐侧后方，**不碰鼠标键盘**。
6. 打印：引导语、任务卡、观察表、访谈问题。

## 3. 引导语（逐字念，不要补充）

> 这是一个还在很早期的世界创作工具。今天不是测你，是测它。
> 你可以随便点、随便试，没有正确做法；遇到看不懂的，不用忍着，直接说出来。
> 这一版的画面是示意，重点看世界怎么反应，不看画面精不精细。
> 我会尽量不说话，除非你卡住了。

念完再补一句：

> 过程中我不会告诉你该点哪里。

**不要提**：Tab、F、空格、拖动、弦、回路、力迫、调性、发布。

## 4. 任务卡（只给受试者看当前一条）

**任务 A · 第一眼（60 秒，不许动鼠标）**
> 先别动。你看到的是什么？如果要把这个界面讲给朋友听，你会怎么说？

**任务 B · 自由探索（3 分钟）**
> 现在可以动了。随便看看，想做什么都行。
> 这里没有「正确操作」。

**任务 C · 改一根（3 分钟）**
> 如果你想让右下角那个小窗口里的世界变一点，你会怎么做？
> 试试看。改完告诉我你改了哪一根。

**任务 D · 圈与菱形（3 分钟）**
> 图里那些圈和菱形是什么？点一下/悬停一下会怎样？
> 你能说出其中一个圈让什么牵动了什么吗？

**任务 E · 换视角（3 分钟）**
> 右下角那个小窗口，有没有办法看大一点？
> 除了现在这个画面，还有没有别的看法？

**任务 F · 发布（3 分钟）**
> 如果你觉得这个世界差不多了，你会按哪里？
> 看到结果后，你觉得那个分数在说什么？

（主持人在这里补一句：**分数是这个世界当前的状态，不是工具的质量。**）

## 5. 观察表（每 30 秒记一次）

| 时间 | 鼠标在哪 | 动作 | 原话 | 备注 |
|---|---|---|---|---|
| 0:00 |  |  |  | 第一眼 |
| 0:30 |  |  |  | 是否碰弦 |
| 1:00 |  |  |  |  |
| … |  |  |  |  |

重点记六个数：

1. **首次注视弦网络的时间**（从页面出现到视线/鼠标进入中央主区）；
2. **首次主动悬停弦的时间**；
3. **首次主动拖动弦的时间**；
4. **是否在 30 秒内碰弦**（通过 / 延迟 / 未发现）；
5. **是否主动点开右下残影**（或按空格）；
6. **是否主动发现 Tab / F**（不提示，只记录）。

## 6. 访谈问题（任务后）

1. 「如果用一个词形容这个界面，你会用什么？」（先记原词，不追问）
2. 「你觉得那些竖线是什么？它们和右下角的小窗口是什么关系？」
3. 「你刚才改的那一根，世界哪里变了？你怎么看出来的？」
4. 「那些圈是做什么的？你为什么点/不点它？」
5. 「五个小词（弦、回路、调性、力迫、和弦）你看到了几个？哪个最清楚，哪个最含糊？」
6. 「如果你要教朋友用这个工具，你会先教他做什么？」
7. 「你觉得这是一个游戏，还是一个做世界的工具？为什么？」
8. 「哪里让你觉得『这还是个网页仪表盘』？」

## 7. 判定标准（先定，再看数据）

**核心命题通过**：5 人中 ≥3 人，在第一分钟**主动**说出以下任一类，且不是被追问出来的：

| 编码 | 表现 | 例句 |
|---|---|---|
| A 编辑器/调律 | 把它描述成可以改世界、调参数、看结构的工具 | 「这是一个调世界的台子」 |
| B 弦/网络 | 把中央竖线/连线读成弦、神经、关系网 | 「这些线是牵一发动全身的」 |
| C 因果/结构 | 主动说改一根会影响别处 | 「我把这个拉高，那边的雨就变密了」 |

**失败信号**：≥3 人第一分钟只说「游戏 / 关卡 / 画面 / 角色」，完全没看中央网络；
或把整页读成「一个游戏加了一个调试面板」。

**次核心通过**：≥3 人在首次注视弦网络后 30 秒内主动悬停或拖动一根弦。

**中间态**：只说「很酷 / 很复杂 / 看不懂」，记录，不计入通过。

## 8. 你需要在测试时重点观察的「游戏感残留」

1. **右下预览窗**：它会不会反而成为第一眼焦点，把中央网络挤成背景？
2. **角色**：蛞蝓猫/蜥蜴画得可辨认，会不会让人只想看它们，忽略弦？
3. **工具栏**：底部的压力/残酷是否仍被读成「难度条」？它们现在只是调性快捷入口。
4. **术语密度**：五个词同时常驻，是帮助还是噪音？哪个词被读出来了？
5. **弦的密度**：23 根弦 + 31 条耦合 + 6 条回路，第一眼是「丰富」还是「糊」？
6. **可拖动性**：弦没有明显的拖动手柄，只有悬停提示；他会不会根本不知道能拖？
7. **视图切换**：空格 / Tab / F 都没有可见按钮；他会不会只停在默认视图？
8. **发布分数**：58 分红区，他会不会把「还站不稳」理解成「这个工具不好用」？

## 9. 视觉「干」的告知与拆分

测试时统一说一句：

> 这一版的画面是示意，重点看世界怎么反应，不看画面精不精细。

但不要在受试者评价画面时辩解。

记录他说的「干」属于哪一类：

| 类型 | 属于 | 下一轮动作 |
|---|---|---|
| 角色不动、没有待机/受击动画 | 内核边界（无动画求解器） | 先接动画求解器或预置动画状态机 |
| 没有声音、没有音乐 | 内核边界（cue 未接音频） | 接 WebAudio/音频通道 |
| 弦网络太密、看不清 | GUI 可改进 | 分层/折叠/缩放，而不是减少弦 |
| 右下预览太小、像缩略图 | GUI 可改进 | 预览尺寸/交互 |
| 文字太多、看不清 | GUI 可改进 | 排版与层级 |
| 「感觉不像游戏」 | 定位正确 | 不修，这正是本轮目标 |

**本轮已定：说。** 引导语和测试前的第一句话都用上面这句，不因为受试者评价画面而辩解。
