# 最小 GUI 用户测试包

> 目的只有一个：验证「非程序员能不能把拖滑块理解成在设计一个让故事发生的压力系统，
> 而不是在调难度」。其他都是副产物。

## 0. 一页速览

| 项 | 值 |
|---|---|
| 人数 | 5 人（非程序员） |
| 单人时长 | 25–30 分钟 |
| 环境 | 桌面浏览器 1440×900，`pnpm gui` 打开的本地页面 |
| 每人间隔 | 清空 `localStorage`（术语计数会累积） |
| 记录 | 屏幕录制 + 观察表 + 访谈录音（征得同意） |
| 核心指标 | 5 人中 ≥3 人主动说出「压力/条件/世界会怎么反应/命运」，而不是「调难度」 |
| 次核心 | Tab 主动按压率、术语卡片打开率、发布页理解率 |

## 1. 招募

- 不写代码；职业尽量分散（编辑、教师、设计、运营、学生均可）。
- 玩过 1–2 款叙事游戏即可，不要招硬核关卡设计师（他们会用行业词污染结果）。
- 没看过 neurou 的任何文档、截图、介绍。
- 每人一份小礼品或时薪；明确说「是测工具，不是测你」。

## 2. 测试前准备（观察者）

1. `pnpm gui`，打开 `http://127.0.0.1:5188/`。
2. 浏览器控制台执行 `localStorage.clear()`，刷新。
3. 窗口 1440×900，缩放 100%，声音关闭（本版无音频输出）。
4. 开录屏（只录屏幕），准备秒表。
5. 观察者坐侧后方，**不碰鼠标键盘**。
6. 打印：引导语、任务卡、观察表、访谈问题。

## 3. 引导语（逐字念，不要补充）

> 这是一个还在很早期的世界创作工具。今天不是测你，是测它。
> 你可以随便点、随便试，没有正确做法；遇到看不懂的，不用忍着，直接说出来。
> 这个版本只有规则和状态，画面是示意，不是最终样子。
> 我会尽量不说话，除非你卡住了。

念完再补一句：

> 过程中我不会告诉你该点哪里。

**不要提**：Tab、滑块、术语、音准仪、结构层。

## 4. 任务卡（只给受试者看当前一条）

**任务 A · 自由探索（3 分钟）**
> 这就是一个世界，它自己在往前走。随便看看，想做什么都行。
> 试试看，能不能让它下出一场不一样的雨。

**任务 B · 有目标（5 分钟）**
> 试着让画面里那只白色的小东西活过这场雨。
> 然后再试一次，这次让它死掉。死了也没关系，我想看它怎么死。

**任务 C · 试玩（4 分钟）**
> 右上角有一个「试玩」。进去玩两局：一局尽量活，一局随便来。
> 玩完回到刚才的画面。

**任务 D · 发布（2 分钟）**
> 点右上角的「发布」，等它出结果。看看这一页在说什么，然后讲给我听。

**任务 E · 回访（2 分钟）**
> 如果这个作品是你做的，你会怎么跟朋友介绍它？

### 5.3 Tab 主动按压记录法（重点）

- 全程不提 Tab；唯一提示是**拖动滑块时右边缘极淡的「Tab」**（透明度约 0.22）。
- 记录四个数：
  1. 首次拖滑块的时间点；
  2. 首次按 Tab 的时间点（没有就记「未按」）；
  3. 是否在首次拖滑块后 30 秒内按；
  4. 按之前说的最后一句话（这决定他是「好奇」还是「被告知」）。
- 统计：`按压人数 / 5`、`首次按压中位时间`、`拖滑块后 30 秒内按压比例`。
- 访谈问题 3 只对已按过的人问；没按过的人不问，避免暗示。

## 6. 访谈问题（按顺序，不引导）

1. 刚才你在做什么？
2. 你拖动下面那两个东西的时候，觉得你在改变什么？
3. （仅对按过 Tab 的人）你刚才按了什么？看到了什么？
4. 「发布」那一页，你觉得它想告诉你什么？
5. 你觉得这个世界是你**设计的**，还是你**调的**？
6. 如果让你向朋友介绍，你会怎么说？
7. 哪里让你觉得「假」或者「空」？
8. 如果只能改一件事，你改什么？

追问规则：

- 不引入任何 neurou 术语；用户说出「弦/回路/力迫/调性」时，问「你说的这个词是什么意思」，不要纠正。
- 用户说「调难度」时，只追问一句：「除了难度，还改变了什么？」不要替他补答案。
- 用户说「调气氛」时，记录为中间态，不追问到通过为止。

## 7. 判定标准（先定，再看数据）

**核心命题通过**：5 人中 ≥3 人，在问题 1 / 2 / 5 中**主动**说出以下任一类，且不是被追问出来的：

| 编码 | 表现 | 例句 |
|---|---|---|
| A 条件/压力 | 提到在制造压力、设定条件、让世界变难/变急 | 「我在让雨来得更快，看它撑不撑得住」 |
| B 命运/故事 | 提到在决定角色会不会死、会不会谈崩 | 「我在决定他们会不会谈崩」 |
| C 系统/因果 | 提到改一处、别处会跟着变 | 「我把这个拉高，那边就掉下去了」 |

**失败信号**：≥3 人只出现「调难度 / 调颜色 / 换滤镜 / 调参数 / 换皮肤」这类描述。

**中间态**：只说「调气氛 / 调感觉」——记录，不计入通过。

**其他指标**（只记录，不设通过线，等你定）：

- Tab 主动按压率；
- 术语卡片打开张数（0–5）；
- 能否用自己的话复述「发布」页的一句话；
- 是否主动重玩（试玩结束后又点一次试玩）。

## 8. 你需要在测试时重点观察的「参数面板感」

以下是我担心的具体交互点，请重点看：

1. **数值显示**：滑块右侧的 `50` 是否让受试者把它读成「难度 50」？观察他是否说「调到 80」而不是「雨变急了」。
2. **两条并排的滑块**：是否被当成「音量/难度」这类设置项，而不是世界性格？
3. **标签措辞**：「压力 ↔ 舒缓」「残酷 ↔ 温情」是否被读成「难度轴」？听他先重复哪个词。
4. **即时变色**：拖动后画面立刻变暗/变红，是否让他以为「只是在换滤镜」，从而忽略几秒后出现的台词？
5. **滑块的位置**：放在底部、和播放器控件很像，是否强化「设置面板」感？
6. **提示语**：「拖动它，世界会跟着变」是否太像说明书？观察他是否读完才敢动。
7. **发布页的分数**：他是否把 62 分理解成「游戏质量分」而不是「这个世界站不站得住」？

## 9. 视觉「干」的告知与拆分

测试时统一说一句：「画面是示意，重点看世界怎么反应。」但不要在受试者评价画面时辩解。

记录他说的「干」属于哪一类：

| 类型 | 属于 | 下一轮动作 |
|---|---|---|
| 角色不动、没有待机/受击动画 | 内核边界（无动画求解器） | 先接动画求解器或预置动画状态机 |
| 没有声音、没有音乐 | 内核边界（cue 未接音频） | 接 WebAudio/音频通道 |
| 没有镜头运动、没有景深 | GUI 可改进 | 加镜头与转场 |
| 背景空、雨太稀 | GUI 可改进 | 加粒子、雾、灯光层次 |
| 文字太多、看不清 | GUI 可改进 | 排版与层级 |
| 「感觉不像游戏」 | 两者都有 | 先补一个可感知的机制反馈循环 |

**建议**：如果本轮的目标是验证概念理解，就在测试前明确告知「画面是示意」；
如果目标是验证「愿不愿意玩」，就不要提前告知，让「干」暴露出来。

## 10. 访谈后立即记录（趁热）

- 受试者走后 5 分钟内，补三条：
  1. 他最像在做什么？（一句话）
  2. 他有没有在某个瞬间「啊」了一下？在哪个动作之后？
  3. 如果只能改一个交互，你会改什么？
- 不要当天汇总五个人的结论；先存原始记录，隔天再编码。

## 11. 伦理

- 知情同意：录屏仅内部使用，可随时停止并删除。
- 不收集姓名、联系方式以外的个人信息。
- 不把受试者的原话断章取义地用于宣传。
