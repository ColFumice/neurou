# IR → 文本 → 写回：调律台成为编辑器

> v0.8 把调律台接回了真实世界（读 `examples/tuner.nro`、逐拍跑 `Universe`、拖弦 inject 写回运行时）。
> v0.9 补上最后一段：**把运行时状态冻结成新的基线，序列化回 `.nro` 文件**。
> v1.4 起写回默认先走**源文本行级 patch**（只改数字、保留注释/排版），
> 只有结构变化才回退本文描述的整图 `serialize(ir)`（见 [写回保真](16-写回保真.md)）。
> 至此「图是唯一真源，文本是它的投影」第一次形成闭环：

```
.nro ──compileText──▶ WorldIR ──Universe──▶ 逐拍状态
  ▲                       │                    │
  │   serialize(ir)       │                    │ 拖弦/拨弦
  └───────────────────────┴──────────── inject ┘
        （写回：把当前值冻结成基线）
```

## 1. 序列化器：`serialize(ir)`

`packages/core/src/serialize.ts`，从 `@neurou/core` 导出。输入一张 `WorldIR`，输出规范 `.nro` 文本。

**规范性**：

- 声明顺序固定：世界 → 实体（含实体弦）→ 全局弦 → 耦合 → 回路 → 规则 → 公理 → 信号 → 曲式 → 结局；
- 每段之间空行，缩进两格；表达式按优先级尽量少括号；数字统一格式（整数原样、浮点最多 6 位）；
- 字符串统一双引号转义；集合写成 `{a, b}`；布尔写 `真/假`。

**往返保证（单测）**：对 `examples/` 的四个世界（core-test / rain-slice / negotiation / tuner）：

1. `compileText(src)` 成功；
2. `compileText(serialize(ir))` 也成功，且**语义图相等**（去掉 span 与生成 id 后逐字段比较）；
3. `serialize(compile(serialize(ir)))` 与第一次输出**逐字节相同**（幂等）。

**有损之处**（IR 不保存，序列化无法还原，文档如实标注）：

| 源信息 | 为什么丢 |
|---|---|
| 注释、空行、原始缩进 | 不是图的一部分 |
| 表达式原写法 | 图里是求值后的结构，括号位置可能变化 |
| 曲式名字 | IR 只保存 `phases` 列表，不保存 form 名 |
| 弦的 `可见` | IR 没有该字段 |
| 耦合的 `描述` | parser 读了但没进图 |

## 2. 命令行：`neurou fmt`

```bash
neurou fmt examples/rain-slice.nro             # 打印规范文本到 stdout
neurou fmt examples/tuner.nro --write          # 就地格式化
neurou fmt examples/tuner.nro --out clean.nro  # 写到新文件
```

它先编译（错误则拒绝格式化），再序列化。适合把历史文件统一成规范形态。

## 3. GUI 写回：拖一下弦，文件真的变了

流程（全在 `packages/gui`）：

```
拖动焦点弦 ──pointermove──▶ onInject(raw, persist=false)   （运行时值实时变，不落盘）
  松手     ──pointerup───▶ onInject(raw, persist=true)
                              │
                              ▼  700ms debounce
                   withCurrentBaselines(IR, Universe)
                              │  把 8 根数值弦的当拍值冻结为新基线
                              ▼
                        serialize(IR)
                              │
                              ▼  POST /__neurou/save
                    Vite dev 中间件（仅 dev）
                              │  只允许 examples/*.nro，原子写（tmp→rename）
                              ▼
                    examples/tuner.nro
```

- 拨弦、键盘拨动、对偶翻转也是**用户手势**，同样会落盘（`persist=true`）；
- `Tab` 演示拨弦、`debug setValue/pluckAt/pressKey`、世界逐拍变化**不落盘**；
- 写回后**不热重载**：调律台继续运行，刷新页面才从新基线开局；
- 刷新时 App 用 `fetch('/__neurou/world')`（`cache: no-store`）读文件，避免 Vite 的 import 缓存拿到旧文本；
- 生产包没有 dev 中间件：`data-save-state=disabled`，文件不会被改（生产冒烟会验证这一点）。

调试属性（`.ink-app` 上）：

| 属性 | 含义 |
|---|---|
| `data-world-file` | 当前世界文件，`examples/tuner.nro` |
| `data-saves` | 本次打开页面成功写回次数 |
| `data-save-state` | `idle` / `saving` / `saved` / `error` / `disabled` |
| `data-loading` | dev 下读世界源码时为 `true`，就绪后 `false` |

## 4. 验收

- **单元**（`packages/core/test/serialize.test.ts`，7 个）：四例往返 + 幂等、改基线再编译、改耦合强度再编译、空图边界（编译会按 NRO2009 拒绝空世界）。
- **GUI**（`scripts/gui-test.mjs`，49 项）：真实拖动 → 等待 debounce → 检查 `data-saves`/`data-save-state` → 用 Node 读 `examples/tuner.nro` 确认「叙事弦 信任 / 基线」变了 → 刷新页面确认从写回值开局 → 恢复原文件再刷新确认初值复原（验收始终把文件还原，不污染仓库）。
- **生产包冒烟**：拖弦后 `data-save-state=disabled`、`data-saves=0`、文件逐字节未变。

最近一次数字：`pnpm test` 83/83、`pnpm test:gui` 49/49；写回实测：拖动后约 0.7–0.8s 状态 `saved`，文件基线从 55 变成拖动后的值，刷新后一致。

## 5. 边界与下一步

- **只写基线，不改结构**：GUI 还不能增删弦/耦合/规则，也不能改阈值——这些要等「结构编辑」；
- **写的是整张图的快照**：一次保存会把所有数值弦的当拍值冻结成基线，不只是被拖的那一根；
- **没有撤销/版本**：写回是覆盖式，靠 git；
- **只支持 dev**：`vite preview` / 静态部署没有写回；世界文件也固定为 `examples/tuner.nro`；
- **序列化不是格式保真**：注释与排版会丢，`neurou fmt` 是规范化而不是「保存原样」。

下一步最有价值的是**结构编辑**（在 GUI 里加/删弦、连耦合、改阈值，再写回整张图），
以及把写回目标从「固定 tuner.nro」扩展为「打开任意世界」（文件选择/最近世界）。
