# 记忆编辑架构重构方案（v1.10.0）

## 1. 新规则改变了什么

新增规则：

1. F12 记忆模式内按 F2：编辑**当前弹奏弦类型**的音色；
2. F12 记忆模式内按 F9：编辑该弦类型的声场/混响效果器；
3. Ctrl+F12：清空所有已叠声部；
4. Ctrl+Delete：删除最近一个声部。

这意味着记忆模式不再只是“视觉滤镜”，而是一个**长期编辑上下文**：

```text
世界 → 当前弦类型 → 声部层 → 采样/音色/效果
```

## 2. 对数据结构的影响

建议引入：

```ts
interface MemorySession {
  id: string;
  worldFile: string;
  focusKind: StringKind;
  focusStringId: string;
  layers: MemoryLayer[];
  createdAt: number;
}

interface MemoryLayer {
  id: string;
  kind: StringKind;
  interface: 'strings' | 'spectrum' | 'effects';
  durationMs: number;
  sampleRef: string;      // IndexedDB key，不是把 AudioBuffer 塞进 IR
  effects: { reverb: number; cutoff: number };
  timbreRef?: string;     // 指向谱 id
  muted: boolean;
}

interface KindMix {
  timbreRef?: string;
  effects: { reverb: number; cutoff: number };
}
```

关键点：

- **世界 IR 不包含 GUI 采样数据**；
- 采样存储与 IR 解耦（IndexedDB / OPFS）；
- 记忆层有自己的 id、目标类型、时间长度与效果快照；
- F2/F9 的编辑对象来自 `focusKind`，不是全局当前谱；
- 撤销/重做应作用在 `MemorySession` 层，而不是散落的组件 state。

## 3. 对前端的影响

当前实现是可行的最小闭环：

- `focusKind` 由 `StringField` 上报；
- F2 在记忆模式下自动选择该类型绑定的谱；
- F9 打开按类型的效果器面板；
- 音频引擎有按类型分开的 dry/wet 总线；
- 采样录音通过 master 的 MediaStream tap；
- 旧循环直接接 destination，避免被再次录音。

但长期看需要：

1. 统一 `editingSession` reducer；
2. 所有编辑界面从该 reducer 读目标；
3. 明确“退出记忆模式”的唯一入口；
4. 层列表/静音/撤销在 HUD 中可见；
5. 快捷键只在目标上下文有效。

## 4. 对后端 / Host 的影响

- `HostSnapshot` **不应**包含音频采样和 GUI 层；
- 若 Host 需要记忆层，应另给 `MemoryLayerDescriptor`，以引用而不是二进制塞进 snapshot；
- 采样持久化放 IndexedDB，Host 只读 metadata；
- 音频引擎与 GUI 的边界用“按类型效果总线 + 采样 tap”表达，避免 Host 依赖浏览器 MediaRecorder。

## 5. 实施顺序

1. **会话模型**：`MemorySession/MemoryLayer` + reducer；
2. **类型路由**：F2 音色、F9 效果器均通过 `focusKind` 统一寻址；
3. **持久化**：采样从内存迁移到 IndexedDB，支持页面刷新恢复；
4. **操作层**：Ctrl+Delete 单层删除、Ctrl+F12 全清、层列表；
5. **Host 扩展**：只读 descriptor 与可选回放接口。
